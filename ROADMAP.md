# Noitis Website Roadmap

The Noitis company website is **publicly launched and accepted** for its current scope.

## Current status — Complete / accepted

- [x] Public Noitis company website available at `https://noitis-mc.github.io/noitis-website/`
- [x] GitHub Pages deployment from `main` through GitHub Actions
- [x] HTTPS on the current public address
- [x] Public access without a GitHub login
- [x] Noitis brand identity, responsive navigation, and light/dark themes
- [x] Product-family presentation with conservative public capability boundaries
- [x] Privacy, Terms, and Trademark pages
- [x] Accessibility, responsive-layout, metadata, link, asset, and browser checks
- [x] Canonical metadata, sitemap, robots, manifest, favicon, and social-preview publication controls
- [x] Production-safe product-link configuration that rejects local/private development destinations
- [x] Deployment health visibility and scheduled live-site health monitoring
- [x] Rollback, emergency-unpublish, and legal/content correction procedures
- [x] Public README aligned with Noitis as a company and product family
- [x] Public repository cleaned of numbered internal development milestone/test labels in the current `main` tree

## Ongoing roadmap

The website is live, but it will continue to evolve as Noitis evolves.

- Add a branded Noitis custom domain when ownership is intentionally purchased and activated.
- Re-run DNS, TLS, canonical-host, redirect, and live-site acceptance checks when a custom domain is introduced.
- Add public product and pricing destinations only after those destinations are real, HTTPS, intentionally public, and reviewed as safe.
- Keep product descriptions synchronized with material changes in the product repositories without presenting planned work as current capability.
- Keep privacy, legal, trademark, and operator information synchronized with actual website behavior and company status.
- Continue dependency review, build validation, browser coverage, and live availability monitoring.
- Reconsider analytics, forms, localization, CMS capability, or other infrastructure only when a concrete business requirement justifies the added privacy and operational complexity.

## Publication principles

The website remains static-first. Public content is treated as production data. Noitis product claims must be factual and conservative, and local/private product addresses must never leak into the production build.

A future custom-domain migration is a hosting upgrade, not a reopening of the accepted public launch. The current GitHub Pages address remains the official public Noitis website until Noitis intentionally replaces it.
